# PWA Configuration Guide

## Features Implemented

### Progressive Web App (PWA)
The application is now configured as a Progressive Web App, providing:
- **Installable**: Users can install the app on their mobile devices
- **Offline Support**: Service worker caches assets for offline use
- **App-like Experience**: Runs in standalone mode without browser chrome
- **Fast Loading**: Cached assets load instantly

## PWA Manifest

Location: `public/manifest.json`

Features:
- App name and description
- Theme colors matching brand (#009963)
- Multiple icon sizes (192x192, 256x256, 384x384, 512x512)
- Standalone display mode
- Portrait orientation
- App shortcuts for quick access
- Screenshots for app stores

## Installation

### Android
1. Open the app in Chrome
2. Tap the menu (⋮)
3. Select "Add to Home Screen"
4. Confirm installation

### iOS
1. Open the app in Safari
2. Tap the Share button (⬆)
3. Scroll and tap "Add to Home Screen"
4. Confirm installation

## Icons Required

Create the following icons and place in `/public`:
- `icon-192x192.png` (192x192px)
- `icon-256x256.png` (256x256px)
- `icon-384x384.png` (384x384px)
- `icon-512x512.png` (512x512px)

Use your brand colors and logo. Icons should be:
- PNG format
- Square aspect ratio
- Transparent or solid background
- Simple, recognizable design

## Service Worker

The service worker is automatically generated by `next-pwa` and provides:
- **Caching Strategy**: Cache-first for static assets
- **Offline Fallback**: Shows cached pages when offline
- **Auto-update**: Updates when new version is deployed

Files cached include:
- HTML pages
- JavaScript bundles
- CSS stylesheets  
- Images and fonts
- API responses (with stale-while-revalidate)

## Testing PWA

### Chrome DevTools
1. Open DevTools (F12)
2. Go to "Application" tab
3. Check:
   - **Manifest**: Shows app info correctly
   - **Service Workers**: Shows active worker
   - **Storage**: Shows cached files

### Lighthouse
1. Open DevTools
2. Go to "Lighthouse" tab
3. Select "Progressive Web App"
4. Run audit
5. Aim for 90+ score

## Performance Optimizations

### Code Splitting
- Automatic route-based splitting
- Dynamic imports for heavy components
- Lazy loading for charts (Recharts)

### Image Optimization
- WebP and AVIF formats
- Lazy loading images
- Responsive images

### Package Optimization
- Tree-shaking unused code
- Minification in production
- Compression (gzip/brotli)

### Bundle Analysis
```powershell
npm run build
```

Check output for bundle sizes. Each route should be under 200KB.

## Offline Behavior

When offline, the app will:
1. Show cached pages
2. Display "Offline" indicator (can be added)
3. Queue failed requests for retry
4. Sync when connection returns

## App Updates

When a new version is deployed:
1. Service worker detects update
2. Downloads new assets in background
3. Prompts user to reload (optional)
4. Activates new version on reload

## Gotchas

1. **HTTPS Required**: PWA only works on HTTPS (localhost is OK for development)
2. **iOS Limitations**: Some features limited on iOS (no background sync, no install prompt)
3. **Cache Invalidation**: Clear service worker cache when debugging
4. **Development Mode**: PWA is disabled in development to allow hot reload
